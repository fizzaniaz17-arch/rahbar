# RAHBAR RAGOps assignment: implementation status

> **Status: PARTIAL.** This is an evidence-led progress report, not a claim that
> the assignment is complete. Experimental limitations and unfinished work are
> called out explicitly.

## System and changes

RAHBAR separates a read-only FastAPI service from the Kubernetes indexer Job.
The API retrieves from persistent Chroma, uses an LLM provider behind an
interface, validates citations, and exposes health and Prometheus endpoints.
The repository includes dev/prod Kustomize overlays, a Chroma StatefulSet,
indexer Job/CronJob, an existing evaluation runner, CI workflows, and earlier
deployment screenshots.

This branch adds incremental vector reuse for unchanged chunks, configurable
recall/citation/abstention release thresholds, MRR and nDCG@5, latency
percentiles, explicit retrieval-service errors, cache exclusion for abstentions
and uncited answers, per-query JSONL traces with inspection/metrics CLIs,
embedding-based query coverage tooling and a 44-query live dataset (32
in-domain, 12 out-of-domain), focused tests, CI manifest/dependency checks,
Kubernetes runbook updates, and four architecture decision records.

The release gate **FAILED**, as it should: recall was below the committed
baseline and there were no citations. The API trace identifies a 404 response
from Ollama's embedding endpoint; `ollama list` on the deployment returned no
installed models. Pulling `nomic-embed-text` was attempted but the Ollama
registry request timed out. No successful model-backed result is claimed.
The newly added 44-query embedding coverage run is also blocked until an
embedding model is available; no coverage percentage is fabricated.

The repository's pre-existing `eval/baseline.json` reports historical scores;
it was not regenerated by this run and is not presented as a result from this
branch.

## Kubernetes and evidence

The existing Minikube deployment was already running when inspected. The
Chroma pod had repeated restarts and was observed near its 1 GiB memory limit.
After checking node headroom (2,057 MiB used, 12%), the Chroma StatefulSet was
updated to request 512 MiB and limit memory to 2 GiB. Its persistent data PVC
was retained; the replacement pod reached Ready with zero restarts and used
146 MiB at the post-rollout sample. The API, UI, Ollama, and Redis deployments
were not rolled out from this branch. Ollama still reports no installed
models. Per-query trace persistence code and its PVC manifest are implemented
locally but were not applied to the live API deployment.

The README retains the pre-existing CI screenshot and now includes a fresh
Swagger UI screenshot from the running `rahbar-real-eval` API:
[`docs/evidence/live-api-docs-2026-11-25.png`](./evidence/live-api-docs-2026-11-25.png).
The capture documents the existing API surface; it does not show the locally
modified API image, a model-backed evaluation, or a candidate rollout. Other
existing screenshots are preserved.

## Local verification

The final local checks passed: API 22 tests with 72.7% coverage (the CI minimum
is 60%), indexer 7 tests, evaluation 8 tests, Ruff across API/indexer/eval/
corpus, mypy for API/indexer/eval, and Kustomize rendering for the dev and prod
overlays. The submission checker reported 163 passes, 4 warnings, and no
failures. Those warnings concern a secret-shaped placeholder, repository
authorship/conventional-commit ratios, and the indexer Job's explicit
`restartPolicy`; they do not prove assignment completeness.

## Remaining work

**PARTIAL:** Incremental embedding reuse has unit coverage, but needs a Chroma
integration run proving unchanged documents make zero embedding requests and
that changed/deleted documents reconcile safely. Trace persistence,
reconstruction, metrics, and coverage code have focused tests, but these new
features have not been deployed with a rebuilt API image. Evaluation metrics
and gates are executable, but no embedding-model evaluation, noise test,
stochasticity pair, 25-question golden set, model-backed 44-query coverage
run, or candidate comparison has been completed.

The Ollama model list is empty and the model registry timed out. Chroma is now
Ready after the memory-limit rollout, but that does not remedy the absent
embedding/LLM models. A new Minikube profile also failed to initialize because
the Docker driver's Windows ACL setup failed.
