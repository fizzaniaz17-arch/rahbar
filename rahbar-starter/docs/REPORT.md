# RAHBAR RAGOps assignment: implementation status

> **Status: PARTIAL.** This is an evidence-led progress report, not a claim that
> the assignment is complete. Experimental limitations and unfinished work are
> called out explicitly.

## System and changes

RAHBAR separates a read-only FastAPI service from the Kubernetes indexer Job.
The API retrieves from persistent Chroma, uses an LLM provider behind an
interface, validates citations, and exposes health and Prometheus endpoints.
The repository includes dev/prod Kustomize overlays, a Chroma StatefulSet,
indexer Job/CronJob, an existing evaluation runner, CI workflows, and earlier
deployment screenshots.

This branch adds incremental vector reuse for unchanged chunks, configurable
recall/citation/abstention release thresholds, MRR and nDCG@5, latency
percentiles, explicit retrieval-service errors, cache exclusion for abstentions
and uncited answers, focused tests, CI manifest/dependency checks, and three
architecture decision records.

## Live evaluation

One 15-question evaluation was run through the existing `rahbar-real-eval`
Minikube profile, namespace `rahbar`, using the API image `rahbar-api:real-eval`,
collection `rahbar-real-600-75`, `nomic-embed-text`, and `llama3.2:3b`.
These are measurements from that deployment, not from a fresh deployment of
this branch. The results and per-question responses are in
[`eval/results/`](../eval/results/).

| Metric | Observed | Interpretation |
| --- | ---: | --- |
| Questions | 15 | Existing golden set |
| Recall@3 / Recall@5 | 0 / 0 | All requests retrieved no passages |
| MRR@5 / nDCG@5 | 0 / 0 | No relevant passage was retrieved |
| Citation validity | N/A | No citations were returned |
| Abstention correctness | 1.0 | The two must-abstain questions were declined, but all answerable questions were also declined |
| API latency p50 / p95 | 0.08s / 0.239s | Captured across this failed-retrieval run; not model answer latency |

The release gate **FAILED**, as it should: recall was below the committed
baseline and there were no citations. The API trace identifies a 404 response
from Ollama's embedding endpoint; `ollama list` on the deployment returned no
installed models. Pulling `nomic-embed-text` was attempted but the Ollama
registry request timed out. A later evaluation attempt timed out while the
existing Chroma pod failed readiness checks. The cluster was already reporting
Chroma near its 1 GiB memory limit and prior OOM kills. No successful
model-backed result is claimed.

The repository's pre-existing `eval/baseline.json` reports historical scores;
it was not regenerated by this run and is not presented as a result from this
branch.

## Kubernetes and evidence

The existing Minikube deployment was already running when inspected. A
read-only `kubectl top pods --containers` sample showed API containers at
11–12m CPU and 261–291 MiB memory, Chroma at 5m and 1012 MiB, Ollama at 1m and
30 MiB, Redis at 30m and 6 MiB, and UI at 1m and 2 MiB. The API Service had
three endpoints and the HPA was at 3/8 replicas with CPU at 11% of its 70%
target. Later in the session the existing Chroma pod became unready and the API
readiness probes failed; no workload or persistent volume was deliberately
reconfigured as part of this branch.

The README links an existing CI screenshot already committed in
`docs/evidence/`; it predates this branch and is not evidence of this session's
live evaluation. Other existing screenshots are preserved. Fresh screenshot
captures of this branch's evaluation and a candidate rollout/rollback have not
been produced.

that changed/deleted documents reconcile safely. Evaluation metrics and gates

pair, 25-question golden set, 40-query coverage run, or candidate comparison

and a healthy Chroma service. The model registry timed out, and the active

to initialize because the Docker driver's Windows ACL setup failed.
