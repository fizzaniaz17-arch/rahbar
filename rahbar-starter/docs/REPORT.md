# RAHBAR RAGOps assignment: implementation status

> **Status: PARTIAL.** This is an evidence-led progress report, not a claim that
> the assignment is complete. Experimental limitations and unfinished work are
> called out explicitly.

## System and changes

RAHBAR separates a read-only FastAPI service from the Kubernetes indexer Job.
The API retrieves from persistent Chroma, uses an LLM provider behind an
interface, validates citations, and exposes health and Prometheus endpoints.
The repository includes dev/prod Kustomize overlays, a Chroma StatefulSet,
indexer Job/CronJob, an existing evaluation runner, CI workflows, and earlier
deployment screenshots.

This branch adds incremental vector reuse for unchanged chunks, configurable
recall/citation/abstention release thresholds, MRR and nDCG@5, latency
percentiles, explicit retrieval-service errors, cache exclusion for abstentions
and uncited answers, per-query JSONL traces with inspection/metrics CLIs,
embedding-based query coverage tooling and a 44-query live dataset (32
in-domain, 12 out-of-domain), focused tests, CI manifest/dependency checks,
Kubernetes runbook updates, and four architecture decision records.

[`eval/results/`](../eval/results/) used the existing `rahbar-real-eval`
Minikube profile and API image `rahbar-api:real-eval`, with collection
`rahbar-real-600-75`. This was not a deployment of the current source branch.

| Recall@3 / Recall@5 | 0 / 0 | All requests retrieved no passages |
| MRR@5 / nDCG@5 | 0 / 0 | No relevant passage was retrieved |
| Citation validity | N/A | No citations were returned |
| Abstention correctness | 1.0 | The two must-abstain questions were declined, but all answerable questions were also declined |
| API latency p50 / p95 | 0.08s / 0.239s | Failed-retrieval run; not model answer latency |

That historical run's release gate **FAILED** because retrieval returned no
passages. Its API trace showed a 404 from Ollama's embedding endpoint, and the
Ollama pod then had no installed models.

Afterward, with user approval, the model files were moved from the Ollama
container layer to the bound `ollama-models` 5 GiB PVC. Their checksums were
verified before replacing the Ollama pod, and all three models
(`llama3.2:1b`, `llama3.2:3b`, and `nomic-embed-text`) remained available after
replacement. The existing profile was retained. With user approval, its
container memory cap was raised in place from 6 GiB to 8 GiB without enabling
swap.

The 1B model completed a 26-question run but abstained on all questions and
failed answer quality. Initial 3B runs timed out during generation, not
retrieval. A bounded-output change and concise-answer prompt reduced generation
time enough to complete all 26 questions. The final live run is
[`live-20261127-3b-retry180.json`](../eval/results/live-20261127-3b-retry180.json)
with per-question evidence in
[`live-20261127-3b-retry180-responses.json`](../eval/results/live-20261127-3b-retry180-responses.json).

| Metric | Final 3B run | Interpretation |
| --- | ---: | --- |
| Questions | 26/26 | Complete run; seven responses were semantic-cache hits and 19 required live generation |
| Recall@3 / Recall@5 | 0.7619 / 0.8571 | Recall@5 failed the configured release gate |

The evaluator does not calculate a faithfulness score. A separate qualitative
review of all 26 responses against cited trace passages found material answer
issues in q07, q10, q17, q21, q22, and q24, plus incomplete details in q05,
q08, q15, q23, and q25. See
[`live-20261127-3b-retry180-faithfulness.md`](../eval/results/live-20261127-3b-retry180-faithfulness.md).
The result is a completed evaluation run, **not a passing release gate** or a
claim that answer faithfulness passed. No successful 44-query coverage or drift
result is available.

The repository's pre-existing `eval/baseline.json` reports historical scores;
it was not regenerated by this run and is not presented as a result from this
branch.

## Kubernetes and evidence

The existing Minikube deployment and Chroma data PVC were retained. The API
prompt/runtime changes were built as `rahbar-api:evalshort` and deployed to
the existing API Deployment; the complete branch overlay was not applied as a
single operation. Live API traces and stage metrics were inspected, but the
trace path is pod-local temporary storage and is not durable across pod
replacement. During the final run the existing profile used up to about
7.73/8 GiB. No Chroma data or PVC was deleted.
