# RAHBAR RAGOps assignment: implementation status

> **Status: PARTIAL.** This is an evidence-led progress report, not a claim that
> the assignment is complete. Experimental limitations and unfinished work are
> called out explicitly.

## System and changes

RAHBAR separates a read-only FastAPI service from the Kubernetes indexer Job.
The API retrieves from persistent Chroma, uses an LLM provider behind an
interface, validates citations, and exposes health and Prometheus endpoints.
The repository includes dev/prod Kustomize overlays, a Chroma StatefulSet,
indexer Job/CronJob, an existing evaluation runner, CI workflows, and earlier
deployment screenshots.

This branch adds incremental vector reuse for unchanged chunks, configurable
recall/citation/abstention release thresholds, MRR and nDCG@5, latency
percentiles, explicit retrieval-service errors, cache exclusion for abstentions
and uncited answers, per-query JSONL traces with inspection/metrics CLIs,
embedding-based query coverage tooling and a 44-query live dataset (32
in-domain, 12 out-of-domain), focused tests, CI manifest/dependency checks,
Kubernetes runbook updates, and four architecture decision records.

## Live evaluation

The historical 15-question evaluation in
[`eval/results/`](../eval/results/) used the existing `rahbar-real-eval`
Minikube profile and API image `rahbar-api:real-eval`, with collection
`rahbar-real-600-75`. This was not a deployment of the current source branch.

| Metric | Historical result | Interpretation |
| --- | ---: | --- |
| Questions | 15 | Existing golden set |
| Recall@3 / Recall@5 | 0 / 0 | All requests retrieved no passages |
| MRR@5 / nDCG@5 | 0 / 0 | No relevant passage was retrieved |
| Citation validity | N/A | No citations were returned |
| Abstention correctness | 1.0 | The two must-abstain questions were declined, but all answerable questions were also declined |
| API latency p50 / p95 | 0.08s / 0.239s | Failed-retrieval run; not model answer latency |

That historical run's release gate **FAILED** because retrieval returned no
passages. Its API trace showed a 404 from Ollama's embedding endpoint, and the
Ollama pod then had no installed models.

Afterward, with user approval, the models `nomic-embed-text` and
`llama3.2:3b` were downloaded into the existing Ollama pod's writable layer,
and registry HTTPS egress was allowed for that pod. A separate live request
through the existing API returned HTTP 200, used the Ollama provider, retrieved
five passages, returned two citations, and answered from context. This is
one-query evidence from the existing deployment, not a full evaluation and
not proof that the current uncommitted source branch was deployed.

A later 26-question live evaluation timed out on its first question and
produced no metrics. During the attempt the existing Minikube container
reached about 5.8/6 GiB memory and high CPU, followed by Kubernetes API TLS
timeouts. Further inference was paused to protect the existing cluster. The
timed-out attempt must not be reported as a completed run or assigned scores.
No successful 44-query coverage or drift result is available.

The repository's pre-existing `eval/baseline.json` reports historical scores;
it was not regenerated by this run and is not presented as a result from this
branch.

## Kubernetes and evidence

evidence records a Chroma resource adjustment and a healthy post-rollout pod;
that historical observation is not a measurement of current cluster

## Remaining work

**PARTIAL:** Incremental embedding reuse has unit coverage, but needs a Chroma
integration run proving unchanged documents make zero embedding requests and
that changed/deleted documents reconcile safely. Trace persistence,
reconstruction, metrics, and coverage code have focused tests, but these new
features have not been deployed with a rebuilt API image. Evaluation metrics
and gates are executable, but no embedding-model evaluation, noise test,
stochasticity pair, 25-question golden set, model-backed 44-query coverage
run, or candidate comparison has been completed.

**BLOCKED:** A full model-backed evaluation did not complete because the
existing Minikube container ran near its 6 GiB memory limit and Kubernetes API
requests timed out. Do not retry inference until the existing cluster has
recovered. The current Ollama models are ephemeral in the pod's writable layer.

**NOT IMPLEMENTED / NOT VERIFIED:** Four-category document verification,
quarantine and version restoration; drift monitoring; a Kubernetes evaluation
Job with candidate/live promotion and rollback; a fresh-cluster run; the
eight-page submission PDF; and a new screenshot appendix. The existing
production overlay does not itself implement candidate promotion.
